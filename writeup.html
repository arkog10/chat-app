ClubChat — Writeup

What, where, and who

Part A: each user-facing action is a Graffiti post. The what is the JSON value, the where is the channels list, and the who is the allowed list (or omitted for public). Below, one block per action.

1. Creating a chat

What Persist a new room: activity: "Create", type: "Chat", a title, a new channel (UUID) for the thread, and published — the channel is where later messages and discovery will point.

Where Post the object to a single app-wide string, DISCOVERY_CHANNEL (e.g. arkoghosh-hw10), so every client with that constant can list the same public directory of groups.

Who Omit allowed so the Create is truly public; do not use allowed: [], which in Graffiti is creator-only, not a public feed.

2. Sending a message

What A message object: activity: "Send", type: "Message", a unique id, the content string, and published.

Where Post only to that chat’s channel (the same UUID that was created with the Create) so every room has its own transcript, separate from discovery and other chats.

Who Omit allowed for an open group: anyone who subscribes to the chat channel in this app can read the full history, similar to a public class channel.

3. Joining a chat

What A membership object: activity: "Join", target set to the chat’s channel UUID, and published — enough for the client to know this identity is in the room.

Where Store it on a private per-user channel session.actor + "/joined", a personal “inbox” for join records that does not need to be mixed into public discovery.

Who Use allowed: [] so only the poster can read that object, which keeps “my joins” out of the global directory while the client can still read its own joined channel to build the Chats list and join logic.

Other design choices

  • The app uses the decentralized Graffiti client, passes null for discover on the directory and on message channels so public objects without allowed are visible, and only the actor/joined stream uses the signed-in session to read private Join records.
  • The sidebar stacks Chats, a placeholder Tasks row, and Discover, and the app auto-posts Join when you create a room or open one you have not joined yet.
  • Unread counts use localStorage last-seen times per chat, not a shared Graffiti object, so “read” is per device.
  • The UI is two panes on wide screens, one column with a back control on narrow viewports, and message chips use actorToHandle with a color keyed off the actor id.
